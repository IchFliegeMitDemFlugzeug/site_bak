# Правила работы с сайтом БТС

## Публикационная папка

`dist/` является готовой production-публикацией сайта и хранится в Git.

После любых изменений, влияющих на сайт, обязательно:

1. изменить исходные файлы в корне проекта;
2. выполнить `npm run build`;
3. проверить, что изменения в `dist/` соответствуют исходникам;
4. включить обновлённый `dist/` в тот же commit.

Не вносить изменения только в `dist/` без соответствующих изменений исходников.

## Production-safe dist

`dist/` должен быть пригоден для прямого переноса на production-сервер без ручной правки файлов.

Поэтому нельзя добавлять в `dist/` staging-специфичные настройки, в том числе:

- `X-Robots-Tag: noindex`;
- запрет индексации, предназначенный только для `stage.btsys.ru`;
- staging-адреса, тестовые домены или временные заглушки.

Изоляция staging от поисковиков задаётся на уровне IIS самого staging-сайта, а не внутри `dist/`.

## IIS

`dist/web.config` — production-safe конфигурация IIS. При изменениях не удалять без необходимости:

- MIME-тип `.webp`;
- защитные HTTP-заголовки;
- Content-Security-Policy;
- обработку фирменной страницы `404.html`.

## Служебные production-файлы

Сборка должна сохранять в `dist/`:

- `404.html`;
- `robots.txt`;
- `sitemap.xml`;
- `web.config`;
- файлы подтверждения Mail.ru и Яндекса;
- BIMI-ресурс в `dist/assets/bimi/`.
